<Step id="two-questions" title="Two different questions">

**AuthN**: who is calling? **AuthZ**: may they do this action on this resource? AuthZ runs on every request.

<Step id="passwords" title="Store passwords for the day you are breached">

Assume the table leaks. Use a **slow, memory-hard hash** (Argon2id, scrypt, bcrypt) tuned to tens of ms, plus a unique random **salt** per user. Never use a fast hash such as SHA-256.

<Compare title="Password storage" sides={[
  { title: "Fast hash, no salt", tone: "bad", points: ["Billions of guesses/s", "One pass cracks everyone", "Same password, same hash"] },
  { title: "Argon2id + salt", tone: "ok", points: ["Tens of ms per guess", "Separate pass per user"] }
]} />

</Step>

<Step id="factors" title="Factors that resist phishing">

Typed codes (SMS, app) can be relayed by a phishing page in seconds. **WebAuthn** and passkeys sign a challenge bound to the site origin, so a look-alike domain gets a useless signature.

<Sequence title="Relay phishing versus WebAuthn" actors={["Victim", "Fake site", "Real site"]} messages={[
  { from: "Victim", to: "Fake site", label: "password + 6-digit code" },
  { from: "Fake site", to: "Real site", label: "relays both: login works", tone: "bad" },
  { from: "Victim", to: "Fake site", label: "WebAuthn signature for fake origin" },
  { from: "Fake site", to: "Real site", label: "wrong origin: rejected", tone: "ok" }
]} caption="NIST SP 800-63B treats SMS as restricted (SIM swap)." />

  prompt="Your admins are targeted by phishing pages that relay credentials to your real login in real time. Which second factor stops this?"
  options={[

<Step id="bola" title="Check the object, every time">

Top of the OWASP API Top 10 (2023): **BOLA / IDOR**. The API authenticates, then loads `/invoices/8812` without checking it is yours. Check permission on **that object**, server-side, every time. Random IDs are not authorisation.

  { id: "api", label: "GET /invoices/8812", kind: "service", x: 50, y: 50, note: "owner == caller?" },
  { id: "db", label: "Invoice 8812", kind: "database", x: 100, y: 50, note: "owned by B" }
]} edges={[{ from: "c", to: "api" }, { from: "api", to: "db", label: "403 / 404 if not owner" }]} />

<Choice
  id="fix-bola"
  objective="prevent-bola"
  prompt="GET /invoices/:id authenticates the caller's token, then returns the invoice with that ID. Users discover they can read others' invoices. What is the correct fix?"
  options={[
    { id: "check", text: "After loading the invoice, verify the caller is allowed to read it (for example, it belongs to their account) and return 404 or 403 if not", correct: true, feedback: "Right. Authorisation is checked against the specific object, on the server, for every request." },
    { id: "uuid", text: "Switch invoice IDs from integers to random UUIDs", feedback: "This hides the IDs but does not check anything. IDs leak through logs, emails and shared links, and then the hole is back." },
    { id: "hide-ui", text: "Remove other users' invoice links from the UI", feedback: "Attackers call the API directly. The UI is not a security boundary." },
    { id: "gateway", text: "Require a valid token at the API gateway", feedback: "The caller already has a valid token. The gateway knows who they are, not whether they own invoice 8812." }
  ]}

</Step>

  options={[

  ]}

<Step id="layers" title="Where each check runs">

Each check runs where the information exists. Only the service that loads the object can decide object-level access.

<Step id="roles" title="Delegation without the password">

**OAuth 2.0** (RFC 6749) replaces sharing your password with a scoped, revocable token.

<Step id="flow" title="The authorisation code flow with PKCE">

The browser carries only a short-lived **code**. Tokens come over a direct back-channel. **PKCE** (RFC 7636) sends a hash (`code_challenge`) out and must present the `code_verifier` back. `state` ties the response to the request.

<Sequence title="Authorisation code flow with PKCE" actors={["Client", "Browser", "Auth server"]} messages={[

  { from: "Browser", to: "Auth server", label: "user signs in, approves scopes" },
  { from: "Auth server", to: "Client", label: "redirect back: code + state" },
  { from: "Client", to: "Auth server", label: "code + code_verifier (back-channel)", tone: "info" },
  { from: "Auth server", to: "Client", label: "access token", tone: "ok" }
]} />

<Step id="pkce" title="What PKCE protects">

On a phone another app can claim the same URL scheme and grab the code. With PKCE the code is useless without the verifier. RFC 9700 recommends PKCE for every client. RFC 7636: 32 random bytes, 43 base64url characters.

<Step id="oidc" title="OpenID Connect: who signed in">

OAuth says what a client may access. **OpenID Connect** adds who: scope `openid` returns a signed **ID token** (aud = the client). The **access token** is for the API. Never send an ID token to an API.

<Compare title="Two tokens, two audiences" sides={[
  { title: "ID token", tone: "info", points: ["Audience: the client", "Proves who signed in", "Has sub, nonce"] },
  { title: "Access token", tone: "ok", points: ["Audience: the resource server", "Says what is allowed", "Send this to APIs"] }
]} />

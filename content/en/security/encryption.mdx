<Step id="in-transit" title="What TLS promises">

TLS 1.3 gives **confidentiality, integrity, server authentication** and, via ephemeral keys, **forward secrecy**. It ends at your server (logs, database see plaintext). **HSTS** stops `http://` downgrade.

<Sequence title="TLS 1.3 handshake" actors={["Client", "Server"]} messages={[
  { from: "Client", to: "Server", label: "ClientHello + key share" },
  { from: "Server", to: "Client", label: "ServerHello + certificate + signature", tone: "info" },
  { from: "Client", to: "Server", label: "Finished: encrypted from here", tone: "ok" }
]} caption="Protects the wire, not either endpoint." />

<Step id="internal" title="Inside the network too">

"Behind the firewall" assumes no insider. Encrypt service traffic and use **mutual TLS**: both sides present certificates, so identity replaces IP trust.

<Step id="handshakes" title="What handshakes cost">

A full handshake costs the server a certificate signature and the client a round trip. **Resumption** skips the signature; connection reuse skips the handshake.

<Compare title="Cost per connection" sides={[
  { title: "Full handshake", tone: "bad", points: ["Server signs with its key", "One round trip"] },
  { title: "Resumption (PSK)", tone: "warn", points: ["No certificate signature"] },
  { title: "Reused connection", tone: "ok", points: ["No handshake at all", "Keep-alive, HTTP/2"] }
]} caption="The resumption rate decides CPU spent on signatures." />

<Step id="at-rest" title="Encryption at rest: which attacker?">

Each layer stops a different attacker. More selective means more protective and more costly (encrypted fields are hard to search).

<Compare title="Encryption at rest" sides={[
  { title: "Disk / volume", tone: "warn", points: ["Stops stolen disk", "Running DB shows plaintext"] },

  { title: "Field-level", tone: "ok", points: ["Keys outside the DB", "SQL injection returns ciphertext", "No normal indexing"] }
]} />

<Step id="nonce-limit" title="Keys wear out: the AES-GCM limit">

AES-GCM needs a **unique nonce** per message. Reuse leaks plaintext XOR and the auth key. With random 96-bit IVs, NIST SP 800-38D caps a key at **2^32 encryptions**. Rotate by usage, not just by calendar.

<Stats title="Random-IV limit" items={[
  { label: "Max per key", value: "2^32", tone: "warn", sub: "≈ 4.3 billion" },
  { label: "At 10,000 msg/s", value: "≈ 5 days", tone: "bad", sub: "4.29e9 / 1e4 s" }
]} caption="Envelope encryption makes rotation cheap." />

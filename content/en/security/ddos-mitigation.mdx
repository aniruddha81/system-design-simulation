<Step id="layers" title="Three kinds of flood">

A distributed denial-of-service attack exhausts some resource from many sources at once. Which resource decides the defence:

- **Volumetric**: fill the network links with bits, often UDP reflected off open servers. Measured in Gbit/s or Tbit/s. Only a network bigger than the attack can absorb it.
- **Protocol**: exhaust connection state in servers, load balancers or firewalls, for example a SYN flood filling TCP's half-open connection table. Measured in packets per second.
- **Application layer**: send valid-looking requests that are expensive to serve, such as search queries, logins or uncached pages. Measured in requests per second; each one may be indistinguishable from a real user.

<Step id="amplification" title="Reflection multiplies the attack">

In a **reflection** attack, bots send small UDP queries with the victim's address forged as the source. Open servers reply, to the victim, with responses many times larger. CISA's 2014 alert lists amplification factors of roughly 28 to 54 for DNS and over 500 for NTP's `monlist` command. In 2018, exposed memcached servers produced amplification in the tens of thousands, and GitHub absorbed a 1.35 Tbit/s attack built this way.

The root fix is upstream: networks that drop packets with forged source addresses, as BCP 38 asks, and servers that do not answer large UDP responses to the internet.

<Step id="anycast" title="Absorb it at the edge">

No single data center can absorb a terabit flood. **Anycast** announces the same IP address from many edge locations, so routing sends each packet to the nearest one. A globally distributed botnet's traffic is therefore split across the edge. Each location drops attack traffic (by protocol, port, signature or rate) and forwards only clean traffic to the origin.

Plan for the worst location, not the average: botnets cluster where compromised devices are dense.

<Step id="protocol" title="SYN floods and connection state">

A TCP server normally stores state for every half-open connection after sending SYN-ACK. A SYN flood sends SYNs from spoofed addresses that never complete, filling that table so real clients cannot connect. RFC 4987 surveys the mitigations; the best known is **SYN cookies**: the server encodes the connection state into its initial sequence number and stores nothing until the client's final ACK proves it is real.

<Step id="application" title="Application-layer floods">

Application floods look like users, so defences combine several weak signals. In 2023 the HTTP/2 **Rapid Reset** technique (CVE-2023-44487) let attackers open and immediately cancel streams, producing floods of hundreds of millions of requests per second against large providers: proof that even protocol features become attack surface.

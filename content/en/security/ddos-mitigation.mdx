<Step id="layers" title="Three kinds of flood">

A DDoS exhausts one resource from many sources. The resource picks the defence.

<Step id="amplification" title="Reflection multiplies the attack">

**Reflection**: bots send small UDP queries with the victim's address forged. Open servers reply to the victim with far larger responses. The root fix is upstream: BCP 38 ingress filtering, and servers that do not answer large UDP to the internet.

<Step id="anycast" title="Absorb it at the edge">

**Anycast** announces one IP from many edge sites, so a global botnet's traffic splits across them. Each site drops attack traffic and forwards only clean traffic. Plan for the worst site: botnets cluster.

<Step id="protocol" title="SYN floods and connection state">

A SYN flood fills the half-open table with spoofed SYNs. **SYN cookies** (RFC 4987) encode state in the sequence number and store nothing until the real ACK returns.

<Sequence title="SYN cookie handshake" actors={["Client", "Server"]} messages={[
  { from: "Client", to: "Server", label: "SYN" },
  { from: "Server", to: "Client", label: "SYN-ACK (cookie), no state kept", tone: "info" },
  { from: "Client", to: "Server", label: "ACK + cookie: connection created", tone: "ok" }
]} caption="Spoofed sources never answer, so they cost no table space." />

<Choice
  id="syn-cookies"
  objective="classify-ddos"
  prompt="Why do SYN cookies defeat a spoofed SYN flood?"
  options={[
    { id: "stateless", text: "The server keeps no state for a connection until the client's ACK returns the cookie, so spoofed SYNs consume nothing", correct: true, feedback: "Right. Spoofed sources never receive the SYN-ACK, so they never complete the handshake and never cost table space." },
    { id: "block", text: "They block IP addresses that send many SYNs", feedback: "Spoofed floods use random source addresses. Blocking by IP would block nothing useful, and SYN cookies do not block anything." },
    { id: "encrypt", text: "They encrypt the handshake", feedback: "They encode state in a sequence number; that is not encryption, and encryption would not stop the flood." },
    { id: "bigger", text: "They make the half-open table larger", feedback: "A larger table only raises the bar a little. SYN cookies remove the need for the table during the attack." }

<Step id="application" title="Application-layer floods">

Application floods look like users, so combine weak signals. HTTP/2 **Rapid Reset** (CVE-2023-44487, 2023) shows protocol features become attack surface.

<Step id="why-gossip" title="Spreading state without a centre">

A cluster of thousands of nodes needs everyone to learn things: who is a member, who looks dead, which schema version is current, CRDT state for a shared counter. Broadcasting from one node does not scale, and that node is a single point of failure. Demers et al. at Xerox PARC (1987) borrowed from epidemiology instead: every node periodically picks a random peer and exchanges what it knows. Information spreads like a rumour.

Gossip is robust because no path is special: a lost message or a crashed node simply means the information arrives by another route a round later. It is also gentle on the network: each node sends a constant number of messages per round, whatever the cluster size.

<Step id="epidemic" title="Logarithmic spread">

In push gossip with fanout 1, each informed node tells one random peer per round. At first the informed set roughly doubles each round, which takes about log₂ N rounds to reach half the cluster. Then it slows: most pushes hit nodes that already know, and the last few holdouts are found only by chance. Pittel (1987) showed the total is about **log₂ N + ln N** rounds. For a million nodes that is roughly 34 rounds; with a one-second round, the cluster learns in well under a minute.

Push-pull gossip, where the contacted peer also sends back what it knows, finishes the tail much faster, because uninformed nodes now pull from informed ones as well as being pushed.

<Step id="fd-properties" title="No failure detector is perfect">

To decide a node is dead, you wait for a heartbeat that does not come. But a missed heartbeat cannot distinguish a crashed node from a slow node, a paused process or a dropped packet. Chandra and Toueg (1996) framed failure detectors by two properties:

- **Completeness**: every crashed node is eventually suspected.
- **Accuracy**: live nodes are not suspected, or at least not forever.

In an asynchronous network, no detector can be both complete and perfectly accurate. Every real detector picks a point on the trade-off: suspect fast and sometimes wrongly, or suspect slowly and seldom wrongly.

<Step id="phi" title="Phi accrual: a suspicion level, not a verdict">

A fixed timeout is a yes/no answer that ignores how regular a node's heartbeats usually are. The **φ accrual failure detector** (Hayashibara et al., 2004) instead outputs a continuous suspicion level. It keeps a window of recent inter-arrival gaps and asks: given that distribution, how unlikely is the current silence? φ = −log₁₀ of that probability. φ = 1 means about a 10% chance the heartbeat is merely late; φ = 3 means 0.1%.

Cassandra approximates the gap distribution as exponential, which gives a simple formula: φ = silence ÷ (mean gap × ln 10). Its default conviction threshold is 8.

<Step id="threshold" title="Choosing the threshold">

The application chooses a threshold on φ. A low threshold suspects quickly and makes mistakes more often; a high threshold suspects slowly and rarely errs. The useful property is that the same threshold adapts: on a jittery network, the mean gap rises and so does the silence needed to reach the same φ.

<Step id="swim" title="SWIM: ask someone else before you accuse">

SWIM (Das, Gupta and Motivala, 2002) reduces false positives in a different way. Each round, a node pings one random member. If there is no reply, it does not declare failure; it asks k other members to ping the target **indirectly**. Only if none of them get a reply is the target marked *suspect*, and the suspicion is gossiped. A suspected node that is actually alive can refute it by gossiping a higher **incarnation number**. Membership changes themselves spread by piggybacking on the pings, infection style.

HashiCorp's memberlist, used by Consul and Serf, is based on SWIM with extensions.

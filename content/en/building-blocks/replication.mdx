<Step id="copies" title="Copies protect different promises">

A leader orders writes; followers copy them and may lag. Sync waits for a stated replica condition; async does not. Say what "acknowledged" means: received, flushed, or applied. Replicas copy accidental deletes too.

<Step id="async-loss" title="A successful write can disappear after failover">

Async follower 2 s behind a 500 writes/s leader: lose the leader and **about 1,000 acknowledged writes** are at risk. Lag in log positions beats a time average.

<Step id="reads" title="Read routing defines the freshness promise">

Update an address, read a lagging follower, see the old value: read-your-writes is broken. Read the leader, or a follower that has applied that log position.

<Step id="quorum" title="Overlap requires a strict inequality">

Write reaches W, read asks R. They must overlap if **R + W > N**.

<Compare title="N = 5, W = 3" sides={[
  { title: "R = 2 (sum 5)", tone: "bad", points: ["Can read the 2 that missed the write"] },
  { title: "R = 3 (sum 6)", tone: "ok", points: ["Always touches a replica with the write"] }
]} caption="Overlap alone does not pick the right version or order concurrent writes. Sloppy quorums break the fixed-set argument." />

<Step id="deletes" title="A deletion needs evidence too">

A **tombstone** records a delete so repair can spread it. Keep it longer than the longest outage plus repair time, or old data returns. Fence the old leader too.

<Choice id="tombstone-retention" objective="explain-replica-repair" prompt="A replica is offline longer than the tombstone retention window, then rejoins with an old value. What is the risk?" options={[
  { id: "resurrection", text: "The old value may be resurrected unless rejoin and repair rules prevent it", correct: true, feedback: "Right. The deletion evidence may be gone, so an obsolete copy can appear to be live data." },

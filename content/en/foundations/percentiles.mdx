<Step id="mean" title="An average can hide the slow users">

99 requests at 10 ms and one at 1,010 ms average 20 ms. One user waited over a second. **p99** = the value at or below which about 99% of observations fall.

<Bars title="Same mean, different experience" log items={[
  { label: "Mean", value: 20, unit: "ms", tone: "ok" },
  { label: "p99 (nearest rank)", value: 10, unit: "ms", tone: "ok" },
  { label: "Slowest request", value: 1010, unit: "ms", tone: "bad" }
]} caption="A stable mean can hide a worse tail." />

<Choice id="mean-tail" objective="diagnose-tail-latency" prompt="Mean latency stays at 20 ms while p99 rises from 80 ms to 900 ms. What should you conclude?" options={[
  { id: "tail", text: "The slow portion of the measured distribution worsened despite a stable mean", correct: true, feedback: "Right. Investigate slow requests and workload groups; the mean alone cannot rule out a user-visible regression." },
  { id: "fine", text: "No user experience changed because the mean is stable", feedback: "The percentile directly shows that the slow portion changed, which the mean can obscure." },
  { id: "every", text: "Every request now takes 900 ms", feedback: "p99 is a quantile, not a statement that all requests equal that duration." }
]} />

</Step>

<Step id="rank" title="Calculate the rank before reading the value">

**Nearest rank = ceil(p × N)**, one-based. The rank is a position, not a time. State sample size, interval and convention.

<Step id="aggregation" title="Do not average machine percentiles">

Quantiles are not means. Merge histogram counts or a mergeable sketch, then compute the percentile. Check bucket width near your SLO.

<Step id="fanout" title="A rare branch delay becomes common in fan-out">

**P(any slow) = 1 − (1 − q)^n**, assuming independent branches. It is a probability at a threshold, not an exact p99.

<Stats title="100 shards, each 1% slow" items={[

]} caption="See Dean and Barroso, The Tail at Scale." />

<Step id="correlation" title="Check the independence assumption">

Shared bottlenecks make delays coincide, so the independence formula overstates. Perfect correlation: parent slow rate equals the single-branch rate.

<Compare title="100 branches, 1% slow each" sides={[
  { title: "Independent", tone: "bad", points: ["Slow events scatter", "About 63.4% of parents slow"] },
  { title: "Perfectly correlated", tone: "ok", points: ["Same 1% of requests", "1% of parents slow"] }
]} caption="Real systems mix both. Trace which branches slow together." />

<Choice id="shared-pause" objective="predict-fanout-tail" prompt="All 100 branches exceed 100 ms on exactly the same 1% of parent requests, and never otherwise. What percent of parents encounter a slow branch?" options={[
  { id: "one", text: "1%, because the slow events coincide perfectly", correct: true, feedback: "Right. These branches are perfectly correlated; the independence formula does not apply." },
  { id: "sixty", text: "About 63.4%, by assuming independent 1% tails", feedback: "That number requires independence, which the scenario explicitly removes." },
  { id: "hundred", text: "100%, because there are 100 branches", feedback: "Adding probabilities double-counts the same slow parent events when branches fail together." }
]} />

</Step>

<Step id="mitigate" title="Reduce tails without causing another queue">

Remove variance first: bound batches, admit load, fix hot partitions, isolate noisy neighbours. Hedge only with spare capacity.

<Compare title="Tail fixes" sides={[

  { title: "Hedged request", tone: "warn", points: ["Extra copy after delay", "Bound the rate", "Worse if saturated"] }
]} />

<Choice id="hedging" objective="diagnose-tail-latency" prompt="A read dependency is saturated and p99 is rising. What is the safest first move?" options={[
  { id: "admission", text: "Control admitted load and investigate the constrained resource", correct: true, feedback: "Right. Creating spare capacity addresses queueing; measure before adding duplicate work." },
  { id: "duplicate", text: "Immediately duplicate every read to the same saturated pool", feedback: "That raises load on the bottleneck. Hedging needs a bounded policy and enough independent spare capacity." },
  { id: "hide", text: "Remove timed-out requests from every dashboard", feedback: "That hides user-visible failures and biases the reported experience toward successes." }
]} />

</Step>

<Step id="measurement" title="Measure the wait the user actually experienced">

Include time spent waiting to start. A timeout is a failure even with no latency sample. Watch latency and availability together.

<Compare title="Shorter timeout, better p99?" sides={[

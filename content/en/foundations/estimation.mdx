<Step id="scope" title="Estimate to choose a design">

Estimate to pick a design, not to get a precise bill. Registered users are not daily users.

]} edges={[{ from: "u", to: "a", label: "active share" }, { from: "a", to: "d", label: "payload, retention" }]} caption="State a baseline and a plausible high case." />

<Choice id="estimation-input" objective="expose-estimate-assumptions" prompt="You know there are ten million registered accounts. What else do you need before deriving request rate?" options={[
  { id: "activity", text: "Active users per period and requests per active user", correct: true, feedback: "Right. Account count alone does not determine activity or API call volume." },
  { id: "same", text: "Nothing; registered accounts equal requests per second", feedback: "Those quantities have different units and no direct conversion without activity assumptions." },
  { id: "shards", text: "Choose a shard count before estimating any traffic", feedback: "First estimate workload and capacity needs so partitioning solves an identified constraint." }
]} />

</Step>

<Step id="qps" title="Turn a day into a peak second">

Divide a day by **86,400 s**, then apply a stated peak factor.

<Stats title="2M users × 12 requests" items={[
  { label: "Per day", value: "24M" },
  { label: "Average", value: "278/s" },
  { label: "Peak × 4", value: "1,111/s", tone: "warn" }
]} caption="Peak factor is an assumption to validate against traces." />

</Step>

<Step id="storage" title="Retention multiplies daily ingestion">

Retention multiplies daily ingestion. Count copies, indexes, backups and free space.

<Stats title="1M × 500 B/day, 90 days" items={[
  { label: "One copy", value: "45 GB" },
  { label: "Three copies", value: "135 GB", tone: "warn", sub: "before indexes and backups" }
]} />

<VariantQuestion template="estimation.storage" />

</Step>

<Step id="memory" title="Hot data includes more than payload">

Hot data costs more than payload. Replicas come after that.

<Bars title="Cache of 10M × 200 B values" items={[
  { label: "Payload", value: 2, unit: "GB", tone: "info" },
  { label: "With keys and overhead (3×)", value: 6, unit: "GB", tone: "warn" }
]} caption="Measure popularity skew; the hottest 1% of keys rarely serve exactly 1% of traffic." />

See [caching](/learn/building-blocks/caching) before promising a hit rate.

</Step>

<Step id="servers" title="Round up after applying usable capacity">

Usable capacity = benchmark × target utilization. Round up.

<Step id="bandwidth" title="Carry the estimate through the response path">

Capacity uses the peak rate; daily volume uses the average. Include internal fan-out: 10 reads per request is 10,000 reads/s at 1,000 requests/s.

<Stats title="1,000 responses/s × 20 kB" items={[
  { label: "Payload", value: "20 MB/s" },
  { label: "Link", value: "160 Mbit/s", tone: "warn" },
  { label: "Per day (constant)", value: "1,728 GB" }
]} />

<Choice id="peak-vs-volume" objective="expose-estimate-assumptions" prompt="You know peak response traffic is four times average. Which rate should estimate total daily bytes under that assumption?" options={[
  { id: "average", text: "Average response rate times bytes per response times seconds/day", correct: true, feedback: "Right. Peak informs capacity, while integrated or average rate informs total volume." },
  { id: "peak", text: "Peak rate times all 86,400 seconds, without stating it as an upper bound", feedback: "That assumes peak lasts all day and would be four times the stated average-volume estimate." },
  { id: "registered", text: "Registered user count alone", feedback: "Volume still needs activity and bytes per operation; account count is not a byte rate." }
]} />

</Step>

<Step id="failure-reserve" title="Ask what remains after a failure">

Normal-state capacity is not an availability plan. Vary the inputs and find what breaks first.

<Choice id="zone-reserve" objective="size-server-count" prompt="Eight servers meet peak at the chosen target, but three are in a zone that may fail. What must you verify?" options={[
